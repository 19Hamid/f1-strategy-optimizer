# Dashboard and API review, 27–28 September 2026

> Historical review snapshot. Its references to a private, one-case hosted preview describe that earlier deployment. The current public static site and its wider catalog are documented in [`website/`](../website/); the React/API client remains a separate local development interface.

## Scope and evidence

The supplied `f1-review-part-aa` passed the accompanying SHA-256 check and
unpacked into the development repository, data, model and reports. All 140
listed manifests matched their 559 recorded file hashes and sizes. The
verified development population covers 68 race partitions (22 in 2022, 22 in
2023, 24 in 2024). Its Phase 8 decision report contains 124 supported choices:
40 in 2022, 42 in 2023, 42 in 2024, across 17 driver codes. Available recorded
target tyres are 48 SOFT, 38 MEDIUM and 38 HARD decisions. A selected target
tyre is the one recorded for that decision; the UI cannot freely substitute a
different tyre. The protected 2025 evaluation was not opened or rerun.

The owner-private hosted Site serves static React files. Without a deployed
FastAPI service, it explicitly shows **one recorded Hamilton example** and
cannot submit another selection or a live scenario job. With the supplied
bundle and local Vite-to-FastAPI proxy, the same client uses the verified
catalog and live API. The private URL is a design and interaction preview, not
a deployed end-to-end analysis service.

## Local journey and checks

- Against real archive artifacts, `GET /api/v1/analysis/decisions` returned 124
  supported choices. Deterministic requests succeeded for a 2022 Bahrain
  Perez SOFT decision, a 2023 Bahrain Verstappen HARD decision and a 2024 Japan
  Hamilton MEDIUM decision. An unsupported decision returned 404 and protected
  season input 422.
- The Japan Hamilton first estimate returned 1539.3593023335823 seconds when
  stopping after the selected lap and 1541.109217525512 seconds when waiting
  one lap, a +1.749915191929631-second advantage toward stopping. These are
  modelled remaining-race times, not actual race outcomes.
- A real 100-scenario job completed in about 90.9 seconds on this CPU. It
  returned `NO_CLEAR_ADVANTAGE`: its central 90% paired-advantage interval was
  approximately -34.52 to +69.85 seconds, crossing zero. Its 62%/38%
  simulated-scenario split describes this batch and is not the chance of a
  correct real-world decision. A missing in-memory job returned 404. Queue,
  cancellation and network failures have meaningful UI test coverage; their
  specific paths were not all reproduced against the real archive.
- Before the final additive full-name change, the full backend suite passed:
  **1,637 passed, 5 skipped**. After that change, Ruff passed on `app` and
  `tests`, and Python 3.12 compiled the edited files and tests. The temporary
  Python 3.14 interpreter disappeared in an environment reset and restoring it
  timed out, so the full suite was **not rerun** after the name addition.
- `npm test` passed **20 frontend tests** and `npm run build` passed after the
  final UI changes. Local Vite and FastAPI HTTP requests returned the page,
  capabilities, catalog and point estimate through the development proxy.
- No full browser-based desktop/mobile, keyboard or reduced-motion walkthrough
  succeeded: the available environment lacked a working Chromium binary and
  its browser download failed. DOM interaction tests and source inspection are
  useful evidence, but do not substitute for those visual and interaction
  checks.

## Model and product limits

The first estimate is one model calculation; the later paired result samples
uncertain scenarios and can disagree. The displayed 90% range reflects the
paired scenario batch, not measured single-lap prediction error, a calibrated
real-world decision probability or validation on a held-out race season. The
source provenance identifies development training seasons 2022–2024. Avoid
claims about future-race accuracy, live telemetry, weather, Safety Cars,
finishing position or win probability. The provided development report does
not independently establish a numeric single-lap error for the UI.

Deploy the API and its verified read-only artifacts separately before enabling
the full picker on the owner-private hosted Site. Confirm cross-origin access,
job polling/cancellation after service restarts, capacity and timeout behavior
for roughly minute-scale 100-scenario requests, then conduct actual desktop
and mobile browser checks with keyboard and reduced motion. Keep the protected
2025 evaluation sealed until its planned gate; add arbitrary tyre selection
only after the model and verified decision contract support it.
