# Dashboard and API review, 27 September 2026

## Verified scope

The hosted Site is owner-private and serves `dist` as static files. Its React
client recognizes a missing `/api/v1/capabilities` route and displays one
recorded 2024-04-R Hamilton example. It does not host FastAPI or let visitors
run another decision. The repository has a verified-decision catalog route,
deterministic route, and bounded in-memory paired jobs, but no reachable API
deployment has been demonstrated for the private Site.

The requested development archive (`f1-review-part-aa` and
`f1-review-sha256.txt`) was named in a file listing but was not attached to the
review environment. Actual 2022–2024 data, reports and model artifacts were
therefore unavailable. This review did not open the protected 2025 evaluation.

## Reproduced issues and changes

| Issue and reproduction | User impact | Change and evidence |
| --- | --- | --- |
| Make `/api/v1/analysis/decisions` reject the request or return an empty catalog. Before the change, the saved Hamilton moment stayed under a “real race moment” heading even though no live selection was verified. | A failed service looked like a usable historical decision. | The picker and analysis now appear only for a confirmed catalog or the explicitly labeled static preview. An unavailable state offers a connection retry. UI test verifies the missing picker and its recovery. |
| Start a paired job, then open Race or Evidence. Previously, progress and cancellation existed only on Answer. | A visitor could not tell whether the job was still running or stop it from another view. | Progress, cancellation, cancellation outcome and job failure render above all three views. UI test switches views while running and after cancellation and failure. |
| Reject a cancellation or a polling request with a temporary connection error. Previously, the same generic paired error offered a new submission while the old job might still occupy the queue. | Duplicate work or unnecessary queue saturation. | The job ID and last progress remain visible. Visitors retry the cancellation or status check. A 404 `JOB_NOT_FOUND` instead clears the old job and offers a fresh run. UI tests cover temporary errors and a job lost on restart. |
| Load a live deterministic response and inspect Answer and the lap chart. Previously, complete action times appeared only in Race; the chart plotted racing lap time without the pit loss. | A newcomer could not compare full remaining times at a glance; the graph visually hid the stop cost. | Answer shows both complete first-estimate times. Evidence plots total lap time including pit loss and marks the pit laps. A fixture with a 20-second stop verifies both values and the chart label. |
| Open Evidence in API-connected mode. Previously, the UI showed a calibration ID and generic provenance but did not inspect the existing verified development-evidence endpoint. | Advanced visitors had little traceable report or model identity. | Evidence now requests `/api/v1/evidence/development` on demand, validates the complete Phase 6–9 response and lists its verified identities. A malformed bundle fails closed. Numeric single-lap prediction error remains unavailable through this endpoint and is stated as such. |

## Checks run and limits

- `npm test`: 17 frontend tests passed after the changes.
- `npm run build`: TypeScript and Vite production build passed.
- `python -m compileall -q backend/app/api integration-check/app`: syntax compilation passed.
- The backend test suite and real analysis were **not** run. This workspace has
  no supplied development bundle, no active Python 3.14 environment and no
  backend deployment for the private Site. Syntax compilation does not verify
  model integrity, real catalog rows, performance or route behavior.
- Browser-based desktop/mobile visual and keyboard walkthroughs of the updated
  Site remain unverified. Frontend DOM interaction tests cover state changes;
  CSS breakpoints and reduced-motion rules were inspected in source only.
